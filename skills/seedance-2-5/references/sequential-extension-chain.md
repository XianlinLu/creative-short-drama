# 单条成片的串行延长主链

本文件用于一条成片需要多轮 Seedance 2.5 生成的任务。它补充基础画布的阶段执行与恢复规则，重点约束“计划中的多个段落”何时可以成为真实视频节点。

## 默认是一条主链

用户要的是一条完整成片，且没有明确选择多镜头并联制作、硬切蒙太奇或多个候选时，默认只建立**一条视频主链**：

```text
起始段 → 延长 1 → 延长 2 → 延长 3 → …… → 最终结果／后期
```

场景数量、剧情段落数量、分镜数量和生成节点数量不是一一对应关系。城市、室内、幻想世界、产品特写或 UI 收束等画面差异，不能单独成为创建多个并联视频节点的依据。先在创作分镜中设计动作、遮挡、光线、形状匹配、视线、运镜或声音桥，让下一场景从当前结果中生长出来，再用视频延长实现。

书本、门、镜子、手机、产品、人物手势、衣料、烟雾等反复承担转场的元素属于**连续性载体**。它不只是视觉主题，还包含上一段实际生成出的形态和动态状态：尺寸、材质、磨损、页厚、开合角度、手的位置、运动方向、形变、光线、相机与声音。只要后段要从这个载体继续变化，就必须从上一段真实视频延长。给多个并联节点同一张参考图，只能提供静态外观参考，不能保证动态边界一致。

只有以下情况可以另开独立视频源或新的延长链：

- 用户明确要硬切蒙太奇、并联制作、多个独立版本或逐镜头独立返修；
- 实时能力确认不支持所需延长，或真实源片无法作为延长输入；
- 上游存在用户不希望继承的问题，继续延长会违背已确认方案；
- 两段必须由不同且互不相容的真实来源开始，无法通过一条延长链实现。

Agent 不能仅凭“换场明显”“分成五幕”“可以加快制作”推断用户同意并联。若独立路线会把一条主链改为多个视频源，且用户尚未授权 Agent 决定该路线，应通过制作确认说明一致性与可修改性的影响并让用户选择；无答复时保留串行主链，不创建并联节点。

## 完整规划，逐段实例化

在 Note 或制作任务表中可以一次规划整条片：每段的剧情任务、预计时长、转场桥、声音接力、目标结束状态和最终顺序都应写清。**规划完整不等于节点全部可建。**

对串行延长主链，任一时刻只允许当前可执行的一段成为新的视频生成节点：

1. 角色短剧先通过[人物资产与对白确认](cast-and-dialogue.md)。首轮只建一个起始视频节点，把本段分镜、出镜角色三视图、正式台词和其他所用素材直连到它，回读输入后再提交。
2. 后续段落继续留在 Note／任务表中，标为“计划中，等待真实上游”。不得提前创建占位视频节点，不得把它们连接到阶段预览，也不得把它们放进当前阶段结构或执行目标。
3. 视频提交后保存任务编号、起始段节点、主链编号、当前段序号、下一段计划和最终目标，按基础画布生命周期交接。不能在同一轮假装上游已完成。
4. 用户随后要求查询或继续时，按基础画布查询同一任务。结果未就绪就保持等待，不改成独立生成绕过依赖。
5. 结果就绪后，读取下一段所需的最小真实边界：人物和物体状态、动作阶段、场景光线、相机、声音以及可用转场触发点。
6. 基于这个真实结果创建或更新**唯一一个**下一段节点，使用实时定义中的视频延长模式，绑定上一段实片，同时直连本段分镜、角色图、正式台词和其他所用素材，核对输入后写入只负责本轮新增内容的 Prompt，并只提交当前这个节点。
7. 保存新任务与新边界计划，交接；下一轮重复查询、理解、创建一个延长节点。直到主链完成。
8. 所有必要真实来源就绪后，才按基础画布选择直接交付、简单顺序结果或精确后期。先核验延长输出是否已包含前段，避免把累计结果重复拼接。

这里的串行不是“先创建五个节点，再依次点运行”。未来节点的模式、真实来源、接续边界和局部 Prompt 都依赖上一轮结果，因此在结果出现前不具备合法配置。基础画布允许上游结果决定下游配置时分阶段推进；本路线必须使用这个阶段例外。

## 当前阶段结构不变量

每次写入与提交前检查：

- 当前新建的视频生成节点是否最多一个；
- 除第一段外，它是否明确使用真实视频延长模式，而非普通文生视频／图生视频；
- 作为延长源的视频是否只有上一段已就绪实片；对应本段的其他素材边及实际输入绑定是否齐备；
- 当前执行目标是否只有本轮节点，没有未来段、预览或最终后期；
- Note 中的未来计划是否仍是计划文字，而不是无来源的生成节点；
- 画布上是否出现多个从同一批素材分叉出去的兄弟 Seedance 节点；若有且用户没有明确选择并联路线，停止提交并改回单链；
- 阶段预览是否只表达已经存在的真实结构，没有被用来为并联生成找理由。

阶段 VideoCompose 或其他预览节点若由基础画布要求建立，只是当前已具备结构的顺序载体。它不是视频生成来源，也不能把五个尚未生成的场景变成五个可并行提交的 Seedance 节点。主链只有一段真实结果时，不用假节点补齐未来顺序。

## 跨场景仍如何延长

生产分镜给每个场景交界指定一个可生成的桥：

| 场景变化 | 可用接续方法 |
| --- | --- |
| 翻书进入不同世界 | 延长当前真实翻页结果，继承同一本书、页厚、手位、翻页方向、纸张形变、镜头和翻页声；新世界从当前页内或遮挡后展开 |
| 城市到室内 | 相机跟随人物进入门、车窗反射、前景遮挡后显出新空间 |
| 现实到幻想 | 粒子、烟雾、布料、闪光或物体形变覆盖画面，再从同一运动方向展开 |
| 产品到故事世界 | 从产品表面纹理、液体、标签图形或包装开合进入下一空间 |
| 实拍到 UI／片尾 | 画面元素收束为图形、镜头推入屏幕、同色块或同形状匹配转场 |
| 节奏明显切换 | 用声音先行、动作落点、短暂黑场或闪白作为延长段内部的转场事件 |

桥的用途是保持主链和可感知连续性，不能为了延长而改写已经确认的剧情。若某个硬切对叙事本身不可替代，则把它作为制作路线选择明确展示；用户确认后才在该断点另开独立链。

例如“连续翻书，每一页进入一个新场景”看似由多个独立世界组成，实际是典型的单链任务。第一段先生成真实书本和第一次翻页；第二段读取这本书的实际页厚、手位、翻动方向和镜头边界，从该结果延长到下一页；后续逐页重复。若把五页分别并联生成，五个节点里的书本、手和翻页运动都可能不同，最后接到同一个预览或剪辑节点也无法恢复连续性。

## 状态记录与恢复

除基础画布要求的状态外，至少保存：

- 主链编号与当前方案版本；
- 计划总段数、当前已完成段序号和下一段剧情任务；
- 当前真实源节点、资源或任务编号；
- 计划结束状态与已观察到的真实结束状态；
- 下一轮延长所需的转场桥、声音接力和局部 Prompt 状态；
- 最终目标是直接使用累计延长结果，还是待真实来源齐备后进入后期。

用户已明确批准整条方案时，后续每轮沿已批准主链继续延长不需要重新确认创意；视频任务仍按基础生命周期分轮交接。用户中途改变剧情、片长、声音、路线或要求暂停时，更新方案与授权状态，再决定是否继续当前链。

## 禁止的伪串行

以下做法都不算逐段延长：

- 一次创建五个普通视频节点，然后说它们按剧情顺序排列；
- 五个节点都连到一个阶段预览，再声称预览会保证连续性；
- 同时提交首段和四个“计划延长段”，即使后四个暂时没有真实源片；
- 用同一张参考图分别生成五段，再依靠后期拼接模拟一条延长链；
- 把同一本书、同一扇门或同一个手势分别交给多个并联节点生成，误以为共享参考图就等于共享动态状态；
- 上游未完成时把下一段改成独立生成，只为避免等待；
- 先写好后四段的最终 Prompt，并在真实边界出现后不重新适配。

如果用户明确选择并联制作，上述并联节点可以作为另一条已确认路线执行，但必须如实说明它不再是“一个一个从真实结果延长”的主链。
