# 知识与产品演示

通用执行与 Prompt 规则按主文件必读项执行；本文仅补充教学结构、真实操作演示与专业准确性审核。

用于科普、课程、实验与设备培训、教程、产品功能演示、SaaS/App 发布视频和帮助中心内容。

## 一、知识培训

### 最小输入

- 一个可验证的学习目标；
- 受众和先备知识；
- 已审核的知识脚本；
- 步骤、概念或部件清单；
- 必须准确呈现的图、公式、参数和操作；
- 检查题或完成标准。

### 结构

```text
提出问题/展示结果 → 解释关键概念 → 分步示范 → 常见错误 → 检查问题
```

每段只解决一个问题。抽象知识可使用示意动画；实际操作、实验步骤和设备流程使用真实素材或经过验证的模拟素材。关键步骤、数值和警告留足理解时间，保持教学顺序与安全要求。

先形成讲解脚本与粗分镜，再核对讲解、操作反馈、理解停顿及必要阅读时间。未指定片长时据此推荐；已有硬性片长不足以覆盖目标时，调整学习目标或拆为章节，不为了适配一次生成而删除关键步骤。一条生成式演示默认沿真实结果逐段延长；需要保持设备、手部操作、页面状态和空间连续时尤其不能并联生成。真实录屏等不同来源可在已确认后期路线中插入；“独立知识点”本身不自动授权并联视频节点。

### 画面规则

- 突出当前讲解对象，弱化无关元素；
- 旁白与对应动作同步；
- 将复杂过程分段，在关键步骤完成后短暂停留；
- 屏幕文字只保留术语、步骤号和关键数值；
- 精确术语、公式、数值和操作标注使用真实素材或后期叠加，不交给生成模型重绘；
- 不让旁白、字幕和画面重复整段文字；
- 不自动补充材料中不存在的事实、公式、参数或历史细节。

### 时间骨架

以下假设讲解与操作计时后确定为 30 秒，仅展示定时分镜，不规定单次生成时长。

```text
0–5 秒：用____现象提出“____”问题，或先展示____结果；
5–12 秒：指出____变量或部件，在画面上突出它，旁白说明它的作用；
12–22 秒：依次演示____步骤，每步完成后停留到观众看清____反馈；
22–27 秒：依据已审核材料展示____常见错误及其____可见后果；
27–30 秒：提出“____”检查问题，让观众判断是否理解本段。
```

按实际脚本、操作和阅读计时重新分配，不擅自删步骤或变速。

## 二、产品功能演示

### 最小输入

- 一个明确的用户任务；
- 已确认的功能路径；
- 干净的真实录屏、产品视频或设备素材；
- 旁白脚本；
- 渠道、比例、已有时长约束、语言和字幕要求；
- 交付版本清单。

不要做“功能大全”。从用户要完成的结果开始。

### 内容结构

```text
使用情境 → 触发动作 → 真实界面/设备操作 → 系统反馈 → 用户结果 → CTA
```

### 真实素材与生成素材分工

- **真实录屏/实拍**：按钮、文字、数据、字段、功能路径、设备操作；
- **Seedance**：使用情境、人物反应、环境、概念画面和过渡；
- **精确剪辑/后期**：光标、放大、标注、字幕、步骤号和 CTA；具体工具与阶段结构由基础画布确定。

不让生成模型重绘关键 UI。界面必须准确时，直接保留真实录屏。

### 提示词骨架

```text
目标：让____用户看懂如何使用____完成____。
真实界面：【操作录屏】中的文字、按钮、数据和操作顺序按原样保留，作为独立实拍/录屏段落使用。
生成内容：开场让用户在____场景中遇到____问题；结尾回到使用情境，展示____结果。
剪辑安排：在开场____动作后接入【操作录屏】，保留____操作与____系统反馈，再接结尾生成片段。不要要求模型把真实 UI 重新生成出来。
声音与节奏：旁白“____”对应____操作，操作完成后留____时间供观众看清反馈，随后进入下一步。
编辑要求：将____时间段/区域中的____改为____；该范围外的内容沿用原片，人物、产品、动作、时间线和声音按原样保持。
```

这是包含生成与剪辑的制作脚本，执行时分配到相应任务；不要整段作为单个生成节点的指令。【操作录屏】为语义占位，按基础画布绑定真实资源。无局部编辑需求时删除“编辑要求”；没有用户要求时不自动添加配乐。

## 三、产品说明与设备培训

- 用“部件—操作—反馈—结果—风险”组织；
- 每步只包含一个动作；
- 安全信息、警告、参数和顺序必须来自正式资料；
- 生成画面不作为最终操作依据；
- 需要真实手部和设备接触时，优先使用实拍、白模或短段参考；
- 由产品、工程或培训负责人审核。

## 四、交付

按已确认需求选择交付，不主动扩展：

- Master；
- 横、竖、方比例；
- 长版与短版；
- 字幕版和无字幕版；
- SRT/VTT；
- 多语言版本；
- 缩略图、脚本和章节时间码。

这些交付应在立项时定义，不在成片后临时猜测。

## 五、专项检查

- 是否只有一个清晰学习目标或用户任务；
- 每段是否只承担一个知识或操作单元；
- 旁白是否与视觉动作同步；
- 所有事实、数值、步骤、UI 和参数是否有来源；
- 关键 UI 是否来自真实录屏；
- 局部编辑是否有时间码、修改项和保持项；
- 是否标记人工专业审核，专业准确性是否交由领域负责人确认；
- 操作、讲解和警告是否留足理解时间；
- 是否定义字幕、比例、语言和附件交付。
