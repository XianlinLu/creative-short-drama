# 输入素材评估与资产准备

有输入图片、视频、音频，或分镜缺少角色、产品、场景与关键帧资产时读取。目标是让素材能承担当前视频任务的明确职责；不把“让视频更好”变成无边界的生图、修改或抽卡。确认与执行遵循[通用制作流程](core-workflow.md)，资源绑定与最终表达遵循[提示词与素材编排](prompt-and-references.md)。

## 两次评估，各自解决不同问题

**需求阶段初评**：先读取用户要求和能够可靠理解的输入，确定每份素材是什么、可提供什么、用户要求改什么和必须保留什么。对计划用于 Seedance 2.5 的候选图片，使用基础画布的只读资源检查取得真实格式、文件大小、像素宽高，再对照当前所选模式的实时输入条件；不凭文件名、缩略图、历史经验或旧版数值判断。按基础画布媒体理解路由：可原生理解时复用原生分析；不可直接读取但画布可取得时使用其指定流程并满足当前授权，不因有附件就必建付费反推节点。未知项标明待核验，只阻塞依赖它的决定。

**分镜阶段复核**：已有剧本和粗分镜后，再判断该素材是否适合具体镜头与拟用模式，例如主体参考、动作参考、首帧或尾帧。此时提出必要的编辑、生图或补充材料方案，与计时和制作设计一起让用户审阅；不在剧情未定时批量生成全部镜头资产。明确且独立的资产编辑请求可先执行，不必等全片剧本完成。

分别检查，不用单个“可用／不可用”标签掩盖问题：

| 检查项 | 判断与处理 |
| --- | --- |
| 技术可接入 | 核验真实资源可访问、格式、`size_bytes`、成对的宽高、由真实宽高得到的比例，以及所选模式的数量／槽位限制；逐项对照当前模型和模式的实时定义，不固定写死上限。字段缺失只把对应项标为未知，不猜值；不能把重新生图当作恢复原件。 |
| 内容可辨认 | 主体、产品关键结构、所需区域和动作是否清楚；遮挡、裁切、模糊是否影响当前职责。增强或重绘不能证明恢复了看不见的真实细节。 |
| 创作可适配 | 形象、服装、场景、光线与已定方向是否相容；构图是否留有动作空间，姿态是否适合动作起点，主体间尺度和站位是否可用。问题要落到具体镜头，不笼统判定“不高级”。 |
| 用户修改与保持项 | 从原话提取要改的对象、区域和目标，以及明确不许改的部分。用户未说要改时，建议与已确认修改分开；有歧义才问，不重复问已有答案。 |
| 事实与一致性 | 人脸身份、产品形状、品牌标识、准确文字、服装和场景连续性是否有可靠依据。不得为统一风格偷偷换身份、改产品结构或虚构不可见的事实。 |

视频、音频同样检查其实际职责及适配性，但图像节点只处理图像资产；不把抽一帧、重绘一张图当作修改了原视频，更不能用生图修改声线、台词或音乐。

## 图片规格预检与挽救优先

对实际准备接入 Seedance 2.5 的每张候选图片，在创建视频节点前完成一次规格预检。大量素材先按职责筛出候选，再检查候选，不为无关附件制造工作。

### 先取得事实，再判断是否超限

1. 从基础画布取得该资源的稳定身份和完整资源引用，调用只读资源检查；记录实际格式、`size_bytes`、`width`、`height`。附件尚未成为可检查的画布资源时，按基础画布的接入流程取得真实资源身份，不能把本地路径、普通 URL 或文件名冒充资源引用。宽高必须成对使用，描述的是素材原始像素，不是画布节点显示框。
2. 读取当前 Seedance 2.5 节点、模型与所选模式的实时输入定义，核对允许格式、单文件大小、像素边长／总像素、宽高比、图片数量、组合与槽位等实际存在的限制。实时定义没有给出的阈值保持未知，不用旧文档、示例或经验补数。
3. 输出一条可理解的结论：哪些规格已满足、哪一项超限或未知、这会阻止直接输入还是只影响构图质量。不要只说“图片不合格”，也不要等视频节点报错后才处理。
4. 技术通过和创作适配分别记录。一张图片即使规格通过，也可能不适合作首帧；一张图片即使规格超限，也可能仍是最可靠的人脸、产品或风格依据。

资源检查是只读动作，不改变原图。用户已经要求制作或允许分析素材时直接完成；只讨论方案且尚未允许读取画布素材时，按基础媒体理解与授权规则处理。

### 技术超限不能成为丢弃理由

只要素材内容仍有价值，就将原图状态记为“保留，需适配”，而不是“不可用／删除”。保留原节点和原始资源，所有修复都创建衍生资产，原图继续承担身份、产品、文字校对或风格依据。不得因为视频节点会报尺寸错误就静默不连接、换成无关图片、从文字重新捏造主体，或擅自降低用户已要求保留的细节。

根据问题给出最少必要路线：

| 发现的问题 | 首选处理 | 何时使用图像生成／编辑模型 |
| --- | --- | --- |
| 文件字节过大，但尺寸、构图和内容合适 | 在当前能力支持时转换为兼容格式、调整编码质量或无损／有损压缩，尽量保持像素与视觉内容 | 普通压缩即可解决时不用生图；只有压缩后质量不足或还需内容修复时再用 |
| 像素边长或总像素过大 | 等比缩小到当前输入范围，保留构图和色彩；不拉伸、不换身份 | 同时需要重构图、去除多余元素或补画面时使用编辑模型 |
| 分辨率过低、主体太小或细节不足 | 优先询问是否有原片、原始导出或更高清版本 | 用户没有更好来源且接受推断性修复时，可做放大、清晰化或参考重生；明确说明生成细节不等于恢复真实细节 |
| 比例超出输入范围或与已确认成片画幅不适配 | 比较裁切、留边／背景填充、扩图和重新构图；保护主体、产品、Logo 与必要文字 | 裁切会伤害关键信息，或需补出真实合理的画面空间时，使用扩图／重构图模型 |
| 格式不受支持 | 在可用能力中做不改变内容的格式转换，并处理透明度、色彩与方向 | 格式转换本身不用生图；透明背景必须转为实体环境或需要重建边缘时可用编辑模型 |
| 构图、姿态、背景、遮挡不适合目标镜头 | 先确认要保持和要改变的区域 | 使用参考生图／图像编辑，明确目标画幅、动作起点、空间、保持项和禁止项 |
| 精确人脸、产品结构、Logo 或文字是核心 | 优先索取更可靠原图，保留原图作校对依据 | 只有用户接受模型可能改动细节时才生成；准确文字与标识优先后期或可靠原素材合成 |

“放大”要区分两种情况：确定性上采样只增加像素，不恢复缺失细节；生成式放大／重绘会推断新细节，可能改变脸、产品、文字或材质。向用户说明当前准备采用哪一种，不能把生成式结果描述成原图真实信息的恢复。

### 用 question 让用户选择修复路线

当技术问题会阻止直接输入，或不同修复路线会明显影响裁切、身份、产品准确性、费用或成片构图时，实际调用宿主 `question` 工具，让用户选择：

- **提供更合适的原图**：适合有人脸、产品、Logo、文字或高精细事实需要保真，且用户可能持有高清／原始文件；
- **优化当前图片**：在保留项清楚后，允许 Agent 使用确定性处理、图像编辑或参考生图生成合规衍生图；
- **调整使用方式**：例如只把原图作身份／风格参考，另做适合首帧的构图，或改变裁切／留边方案。

不要只问“要不要继续”，要同时说明检测到的真实问题、模型要求和推荐选项。若用户已经明确说“没有更好的图，帮我优化后直接做”，视为优化路线和对应执行范围已给出，不重复询问；仍需说明使用的方法和会保留的内容。若用户尚未授权修改，不能以“避免报错”为由自行重绘。若问题不阻塞内容创作，把这组选项并入内容母版后的集中 question；若可靠主体本身无法确定、会让剧情或资产方案失去依据，可提前询问素材路线，这属于必要资源决定，不是提前让参数限制创作。

用户选择提供更好原图时，保留当前方案和素材职责，等待新资源，不把旧图删掉；选择优化时进入下面的衍生资产流程；用户没有回答时保持“待选择”，不提交依赖它的视频任务，也不擅自放弃素材。

### 优化后必须重新预检

衍生图片就绪后，对实际输出再次执行资源检查，并对照同一 Seedance 2.5 模式复核格式、字节大小、宽高、比例和数量限制。只有真实衍生资源通过技术条件、必要保持项已落实且约定的用户选择完成后，才把它绑定到视频节点。生成任务成功或画布上出现缩略图都不能代替这一步。

若衍生图仍超限，优先修正当前衍生资产，不重复从原图无目的抽卡；无法在现有能力中合规处理时，保留原件和已生成结果，说明具体阻塞并请用户提供新来源或选择替代路线。

## 选择最少必要处理

| 素材结论／用户意图 | 处理路线 |
| --- | --- |
| 素材与职责均匹配，未要求修改 | 直接复用，不默认先“优化”一遍。 |
| 主体可辨认，但不适合镜头构图 | 仍可作主体参考；若确需首帧、动作起点或指定构图，再提出图像编辑／重构图方案。 |
| 用户要换装、换背景或局部修改 | 选择支持相应输入和编辑方式的图像节点，写清修改范围与保持项；若目的仅是改变视频中的呈现且已选模式可直接完成，可在视频阶段落实，避免重复改图。 |
| 画幅或取景不适配 | 比较裁切、完整显示、扩图或重新构图对主体与信息的影响。能用已支持的确定性处理解决时不必生图；会裁掉关键内容或改变画面时先提出取舍，不拉伸主体凑比例。 |
| 缺少必要角色、环境、道具或关键帧 | 按分镜补最小必要资产；有身份或产品依据时用参考生图／编辑保持一致，无依据的创意资产才从描述新生成。 |
| 原素材不足以完成目标，或用户要求重做 | 说明哪些信息无法保留、为什么需要重做；在已授权范围内重新生成，保留原件。不能把“无法识别”当作擅自另造人物或产品的依据。 |
| 保留原视频，仅改其中指定元素 | 按视频编辑路线处理；需要替换人物／物体参考时才增加图像资产阶段。参考重做与原片编辑不得混用。 |

### 针对 Seedance 2.5 的资产设计

- **主体与场景参考**：保留可靠身份依据，明确每张图的职责；只在镜头需要时补视角或场景。不同角色不混在难以辨认的集合图中，风格图不自动变成身份参考。
- **首帧与尾帧**：首帧服务动作起点，尾帧服务目标结束状态；画幅、空间、姿态和光线相容，预留可执行的动作路径。若要“拿起杯子”，不把已经举杯完成的姿势误作必要起点。是否使用首尾帧及输入要求以当前模式为准，不保证精确到帧。
- **关键帧与故事板**：只有明确构图、连续性或复杂调度需求时才制作。独立关键帧与多宫格的用途分开，按当前能力决定拆分；不默认每个镜头都先生图，也不把带说明文字、轨迹线或界面边框的图当干净成片参考。
- **精确产品与文字**：优先保留可靠产品素材和准确标识；必要时用已支持的后期叠加或合成处理。重绘、放大或“高清修复”不保证文字、结构和身份准确。
- **参考数量**：只绑定对该视频任务有作用的素材。衍生图已承担目标职责时，原图不自动也接入同一节点；确需原图维持身份、衍生图提供构图时，明确分工，避免互相矛盾。

这些是输入设计方法，不是模型效果保证；不把所有缺点都推给视频模型，也不承诺预处理后必然得到好视频。

## 把修改落实为资产任务

在现有方案 Note 中加入简短素材清单，不另建重复笔记。按任务需要记录：

```text
素材业务名／来源 | 对应镜头与职责 | 格式／字节大小／像素尺寸／比例
| 当前 Seedance 模式技术结论与依据 | 已观察内容问题／待核验项
| 用户要求的修改与保持项 | 建议处理及理由
| 直接复用／图像编辑／参考生图／从零生图／待补充
| 原件／衍生件关系 | 输出用途与依赖
| 已确认／委托／待反馈 | 计划／在途／技术通过／就绪
```

向用户说明具体变化、保留内容、必要新增节点及费用影响，把素材方案纳入原有制作确认，不每张图另起一轮询问。已明确要求“把图的背景换成室内，其他不变，直接生成”的请求可直接进入该资产阶段；不将这句话扩展成视频生成授权。“先看看这张图能不能用”“先别生成”只允许评估和方案，不能启动生图。

整片方案已含必要资产编辑／补图且用户让开始时，无须逐节点重复审批。核心人物、产品形态、视觉方向仍待选择时先展示建议并等待；重要的形象定稿可以在方案里约定先出图、用户选定后再做视频。用户明确委托整套素材设计并直接制作时，在该范围内继续，不机械增加审图关卡。新增付费步骤、超出预算、额外候选或实质改动仍按通用授权规则处理。

## 生图节点与视频节点的衔接

1. **发现适用能力**：使用基础画布实时节点与模型目录，核对格式转换、缩放／压缩等确定性能力，以及单图编辑、多参考融合、局部处理、扩图、放大、画幅重排等生成能力；读取质量层图像创作方法及所选模型参考。简单技术适配优先使用不会重画内容的能力；需要补画面、改构图、换背景、改姿态或推断细节时再选图像模型。不硬编码某个模型或内部身份，不存在适用能力时展示可行替代方案，不假装执行。
2. **写资产 Prompt**：写清用途、来源职责、目标构图／姿态／环境、修改范围、保持项和必要融合要求。图像 Prompt 描述需要得到的静态资产，视频 Prompt 描述其后的动作与变化；不把完整影片时间线塞进生图节点。默认自然语言跟随当前 Prompt 约定；其他图像模型若确有专属格式要求，仅在该节点适用，不改变 Seedance Prompt 或用户对话语言。
3. **建立真实依赖**：保留原始输入，按当前节点保护和写入规则创建或更新衍生资产节点；原素材进入转换、图像编辑／参考生图节点，衍生结果通过重新预检后再作为 Seedance 的明确输入。原图与衍生图分别标明职责；衍生图用于首帧时，原图可继续仅作身份／产品校对依据，但不因“保险”把互相冲突的两张图都绑定。计划中的图片不等于已产生资源，Note 与反推分析不直接接到生成节点。当前阶段结构、绑定和执行目标必须满足基础画布屏障。
4. **按阶段执行**：需要用户选图、真实输出身份或后续输入尚未确定时，先执行获准的图像资产阶段，保存视频阶段待办。只有基础流程允许、全部角色和依赖可确定且授权覆盖时，才组合编排图像与视频执行。图片短任务能否等待按基础规则判断；含视频的执行图必须遵守视频非等待提交与交接，不能以“先出图”为名绕过。
5. **交接到视频**：核验任务状态、真实资源、输出数量、输入映射及技术属性；对实际衍生输出重新检查格式、字节大小、宽高和比例，并与当前 Seedance 2.5 模式限制比较。有约定的用户审图点时先展示并等待。复用已成功且技术通过的资产结果，按基础画布固定实际来源与执行目标，不为启动视频重复执行已经完成的生图任务。默认不做生成后的自动观感评分或重抽；这里的规格复核是输入安全检查，不是审美打分。后续确需理解衍生图中尚不明确的具体信息时，先按基础媒体理解路由与授权补齐，不能把计划描述当作实际结果；不借此扩大为全面质检。来源失败、属性未知、仍然超限、不可用或关键选择未定时，不提交依赖它的视频，也不放弃原素材。
6. **同步当前版本**：将最终选用的素材与职责更新到同一份 Note、制作任务表和实际节点绑定；视频 Prompt 依据当前素材组织，去掉已完成的改图指令和旧状态描述。例如背景已经改成室内后，视频写“人物在室内起身走向门口”，不再要求视频模型先把原背景替换一次。原件仅在仍有明确职责时继续引用。

资产生成完成不等于已确认形象，更不等于视频已完成。默认不因主观质量判断自动换模型、再生一轮或增加候选；用户要求修订时只更新受影响资产和依赖它的任务，保留其他已确认内容。
