# 通用制作流程

本文件维护创作阶段、规格确认、制作路线、音乐、规划与修订。剧本和计时见[故事、分镜与计时](story-and-timing.md)，最终描述见[提示词与素材编排](prompt-and-references.md)。节点协议与执行恢复交给基础画布，不在此另建命令流程。

## 目标、约束与任务分流

用一句话明确为谁、在哪个渠道、表达什么，让观众理解、相信、感受或完成什么。整理用户已经给出的硬约束、可调整偏好和待推荐项；没有给出的画幅、时长及生成规格保持未知，不在内容循环前追问，也不先补默认值。按[内容先行的三层循环](creative-development-loop.md)完成内容母版和所需时长估算后，再进入 question 关口。

| 输入与意图 | 创作路线 |
| --- | --- |
| 从零创作或参考素材重新设计 | 内容设计 → 计时 → 任务拆分 |
| 保留原片，只修改指定元素 | 修改范围与保持项 → 当前编辑模式与继承规格 |
| 已有视频已满足目标，只需组接或包装 | 后期时间线，不重复生成 |
| 续写既有视频 | 下一事件、真实源片边界与新增时间 |
| 两段间过渡 | 可连接的动作、空间、声音与原片保持范围 |

同时要求原片其余不变和重做剧情、改片长等不相容目标时，集中确认取舍。用户已指定、已确认或已授权 Agent 决定的项不重复问，Agent 自己能推导不等于用户已确认。

有输入素材时，先按[输入素材评估与资产准备](asset-preparation.md)完成内容初评、修改要求和保持项提取；粗分镜形成后复核镜头适配性。区分技术可接入、可承担参考职责和可直接用作首帧，不把它们视为同一结论。只有素材需要变化或补齐时才编排图像编辑／生图任务。

## 推荐、确认与执行分别记录

对影响成片的决定，区分“用户已指定／确认”“用户授权 Agent 决定”“Agent 建议、待反馈”。生成授权再单独记录其对应的方案版本、阶段、候选数量和费用边界。Agent 觉得方案完整、模型支持该参数、默认值可用，都不是用户确认的证据。

新手拍第一集按[帮我拍第一集](first-episode.md)处理。将下述内容、规格与素材开工确认合并到故事卡，以一次明确选择确认展示的声音组合；人物与正式对白完成后再征求整集投产确认。以下是其他项目的通用安排。

默认给用户两个有实际作用的参与点，首次 question 必须位于创意、剧本、创作分镜循环之后；完整已确认或已委托的项跳过，不机械凑提问次数：

1. **内容反馈与规格确认**：先完成内容母版，展示创意、剧本／分镜摘要和内容所需片长依据，再用 question 征求内容意见并补齐缺失的画幅、硬性片长、清晰度及影响结构的声音选择。已有用户剧本、明确方向或自由创作委托时，不重复询问已决定内容，但仍先完成对应检查循环；尚未回答的规格继续提问。
2. **制作确认**：内容反馈处理完后，集中展示当前内容版本、最终片长与画幅、素材修改／补图、质量档、延长／独立镜头／后期路线，以及本次准备执行哪些步骤。仅提问仍待决定的项，并明确是在确认方案还是开始制作。短任务可把两次确认合并在内容循环后的一个 question 中；完整已授权方案不重复过关。

需要上述反馈时，实际调用宿主的 question 交互提问工具；等价名称与参数以宿主注册 Schema 为准，不编造工具调用。工具可用时不得以普通聊天问句或一段“方案如下”替代。只有未提供、当前模式不可用或调用失败时才解释并改为聊天提问，仍等待答复。画布项目的详细剧本按下文保存为用户可见的 Note，聊天给出摘要和位置；question 呈现用户需要作的选择，不能只在隐藏计划或节点里写好后宣称已获认可。

| 用户表达 | 可以推进 | 仍不能推断 |
| --- | --- | --- |
| “帮我做个温暖短片”且关键创作未定 | 整理需求、提出方向与初步方案 | 用户接受 Agent 自定的剧情、片长、档位与付费步骤 |
| “时长你决定”“剧情你发挥” | 在该项范围内作决定 | 其他规格、无限费用或自动开始生成 |
| “故事可以”“30 秒可以” | 确认对应故事或时长，完善其余方案 | 其他待定项已获批，或已经授权生成 |
| “方案通过，按这个开始生成” | 按已展示且无未决关键项的方案执行 | 新候选、新增任务或后续实质改动 |
| “规格和剧情都你定，直接生成一条” | 按明确委托选定并执行，说明采用的方案 | 超出一条候选、另设未授权付费试制或违反预算 |
| “先别生成，改一下结尾” | 修订结尾并展示影响 | 执行旧版或把修订当成新一轮生成授权 |

没有答复就保持等待状态；结束当前回复让用户表达意见，不在后台提交依赖未决项的任务，也不为绕过待确认而先生成资产、试片或音乐。

## question 提问关口

### 先问什么，后问什么

| 项目 | 触发时机与提问内容 | 可以不再询问的依据 |
| --- | --- | --- |
| 内容反馈 | 创意、剧本和创作分镜至少完成一次起草—检查—修订循环后，展示当前母版摘要并询问需要调整的方向。 | 用户已明确提供或委托相应内容时不重复问开放题，但仍完成内部检查；已有明确生成授权也不允许跳过内容循环。 |
| 画幅／尺寸 | 内容母版形成后，询问横竖屏、比例或指定宽高。创作分镜先表达空间和镜头意图；确认画幅后再做精确构图适配。用户只说投放平台、上传竖图时，可给推荐但不能自动当成输出选择。 | 用户已明确指定或批准具体画幅、明确委托尺寸选择；当前模式有经核验的固定继承规则。 |
| 成片总时长 | 内容母版与粗分镜计时后，给内容所需值或区间及依据，询问是否接受或另有硬性目标；单次生成长度后续映射，不用其上限替代总片长。 | 已指定／确认且内容循环验证可满足的总片长，或明确委托 Agent 最终决定；原片编辑按模式继承。 |
| 清晰度／质量档 | 实时能力明确后，在依赖此项的制作前询问；仅展示当前模式实际可选档位与可知的成本／耗时差别。不把画幅比例当分辨率，也不把“高清”擅自解释成最高付费档。 | 用户已指定／确认、明确委托决定，或当前模式仅有一个合法值／固定继承。没有该可选项时不虚设问题。 |
| 声音主模式、人声与执行范围 | 第一次询问生成声音时，先按下文给出“纯效果音／带背景音／无声音”；对白、旁白、口型和原声保留在需要时另列问题。与制作确认集中询问，并区分“仅完善方案”和“按展示方案开始制作”。 | 用户已有明确声音组合或委托，且执行请求覆盖当前展示方案与费用边界。 |

固定模式只说明经核验的继承项，不询问不可变参数；用户要求改变锁定项时询问路线取舍，不静默改模式。仅讨论概念或要求先写文字脚本时，可先完成不依赖规格的文字工作，不为表格完整强求尺寸；一旦进入实际视频制作或依赖规格的分镜／资产设计，按本关口补齐。

### 工具调用与回复处理

1. 整理每个关键项的值、状态和依据：**待确认／用户已指定或确认／用户明确委托／模式固定继承**。依据来自用户原话、实际回复或实时模式定义，不来自 Agent 自己的计划。素材尺寸是来源事实；模型默认值、质量建议、平台惯例均不是用户答案。
2. 提问前给足判断所需的简明方案。question 只包含本阶段仍缺的选择；在工具允许范围内批量呈现，问题与选项用当前对话语言。可把“采用推荐值”“由你决定此项”作为清楚的选项，但预选不等于选择，也不把多个互不相同的决定藏在一个含糊的“可以吗”中。
3. 实际调用 question。遵守工具的题数与选项限制，超出时按依赖分批，不用虚构字段一次塞入。异步工具返回、请求已显示、空回答、关闭窗口、超时和工具失败均不是用户答复。等待时仅继续不依赖回答且未被要求暂停的工作。
4. 读取用户实际答复，只更新被回答的项；漏答项保持待确认。用户自由文本同样有效，不强迫其重新点按钮。若问题明确问“是否按上述完整方案开始生成”，用户回答“开始”可覆盖该完整方案；若只问故事或时长，“可以”不能扩展为其他规格与付费生成授权。
5. 将选择同步到当前 Note、制作任务和待写入参数。继续前重查当前阶段所依赖的关键项；只要仍有待确认，就停在对应问题，不创建或提交依赖它的生成任务。不先启动依赖未定画幅的生图来绕过视频规格确认。独立且已获准的素材编辑、非执行 Note 保存仍按各自范围进行。

关键规格是在产品方案阶段要解决的用户选择。基础画布“未指定可选参数使用默认值”适用于方案已确定后其余可选技术参数，不用于替代这里未完成的画幅、成片时长和可选清晰度决定；不因此询问每个底层参数，也不改变基础执行协议。

### 提问内容示例

用户只说“用这张产品图做个广告”时，先完成素材初评、创意、剧本、创作分镜循环和内容估时，形成一版可审阅母版；然后调用 question，询问内容方向、希望的画幅，以及是否接受推荐片长或另有硬性目标。不能一收到请求就先问参数，也不能直接输出“我将制作竖屏 15 秒高清广告”然后执行。

用户反馈修改故事时，先回到相应内容循环，更新剧本、分镜和计时，再调用 question 确认新版本仍缺的选择。内容获得确认后，才询问或确认实时可选清晰度与是否开始制作。问句、选项和推荐理由写入真实工具参数，不只是作为聊天示例输出；不同任务按实际缺项调整，不照抄示例数值。

若用户已经明确“画幅、时长、质量都由你决定，按预算直接做”，则记录委托和预算，在其范围内选定并执行；“帮我做”“快点”“剧情你发挥”不等于对全部规格的委托。

### 声音主模式必须明确三选一

用户尚未明确生成声音安排时，在内容母版完成后的第一次声音 question 中优先使用以下三个互斥选项。标签保持简短，说明写进选项描述；不要只问“要不要声音”“是否生成音频”或“有声／无声”。

| 选项 | 明确定义 | Prompt 与制作含义 |
| --- | --- | --- |
| **纯效果音** | 只生成动作声、物体接触声、自然环境声和必要拟音；不含对白、旁白、歌声或背景音乐。 | 按镜头写具体声源与落点，明确无人声、无 BGM；不能因环境声持续存在就擅自增加音乐。 |
| **带背景音** | 在必要效果音之外，加入持续铺底的背景音乐或氛围背景声；是否含人声仍由独立选择决定。 | 说明背景音的叙事作用、情绪和连续性路线，并保留必要效果音；不把“带背景音”简化成只生成一条 BGM。 |
| **无声音** | 输出不生成对白、旁白、歌声、环境声、动作音效或背景音乐。 | Prompt 明确无任何声音；如计划后期配音／配乐，记录为后期任务，不能称为当前视频自带声音。 |

根据当前内容可以在说明中给出专业推荐，但三个选项都须可辨认，推荐或工具预选不等于用户答复。用户已经明确“保留对白但不要 BGM”“只要原声”“后期统一配乐”等更具体组合时，直接记录该组合，不强迫改选三项，也不重复询问。

声音主模式不替代**人声决定**。内容母版含对白、旁白、歌声、口型表演或需保留原片人声时，在同一批 question 中另问或确认：生成／保留什么人声、由谁说、使用何种语言，以及是否需口型同步。不得把“带背景音”当作默认包含人声，也不得让“纯效果音”暗中保留对白。

用户选择与当前内容冲突时，先说明影响并回到相应循环：

- 有关键对白却选择“纯效果音”或“无声音”：回到剧本循环，确认删去对白、改成画面／文字表达，还是改选允许人声的自定义组合；不能静默丢台词。
- 声音承担转折或节奏信息却选择“无声音”：回到剧本和创作分镜，把必要信息改为可见表达并重新计时。
- 选择“带背景音”：只确定存在铺底声音，不自动授权额外音乐生成节点、曲目数量或无限费用；音乐来源与后期路线仍按下文确认。

将声音主模式、人声决定、声音来源和确认状态同步到内容母版 Note、生产分镜、任务表及最终 Prompt。只要依赖它的生成仍未确认，就停在 question 关口；用户反馈后完整重写相关 Prompt，不在末尾追加一句“不要音乐”或“静音”。

## 三阶段主流程

### 一、创作设计

先按内容循环完成创意、场景剧本及创作分镜，再请求方向反馈；故事围绕人物行动与变化，广告或教学围绕信息结构、演示过程与文案。声音在此阶段参与设计，提出对白、旁白、环境音、动作音效及音乐需要，不把 Agent 的声音建议直接当成用户选择。

只把用户原始要求中的片长、固定配音、原片保持项和画幅作为创作条件。内容母版形成前不按单次生成上限切故事，不用分辨率、生成档位、节点结构、模型示例或 Prompt 模板反推剧情。基础安全与媒体理解规则可以早读，生产能力与参数在内容循环后映射。

完成条件：创意、剧本、创作分镜各自至少经过一次有实质检查的起草—检查—修订，必要事件或信息有画面载体，关键对白与动作具体，形成可审阅内容母版。用户意见尚未取得时标为草稿；明确委托范围不免除内容循环，只免除重复询问已委托的选择。

画布故事、多镜头及结构化短片形成可审阅内容母版后，在本阶段按基础画布笔记流程创建或更新“创作与分镜方案”Note，保存完整剧本、创作分镜和内容所需片长估算。用户尚未认可的内容及未确认的交付片长／画幅标为草稿或待决定。准备请用户审阅时先完成笔记保存并反馈位置，不拖到执行阶段，也不拿整片规格未定作为跳过独立笔记写入的理由；笔记本身的当前阶段结构与写入屏障仍须满足。

### 二、计时与制作设计

1. 根据动作、自然语速、反应、停顿和阅读时间估算；区分并行与串行。低成本读稿或已有音频可用于校准，额外付费试制另行纳入授权。
2. 形成定时分镜及推荐总片长。若与硬约束不相容，具体说明删去、改写或延长哪一部分；不偷偷加速、截断或改时长。
3. 根据连续性、可复用素材、可修改性和实时能力推荐制作路线，再拟定生成任务。一条成片需要多轮视频生成时默认采用[串行延长主链](sequential-extension-chain.md)，场景数不直接转成并联节点数。对照分镜复核素材职责，列出直接复用、用户要求修改、必要补图或重做的范围，按资产准备流程规划适用图像节点及其视频依赖。未获路线选择授权时把建议交给用户决定；资产先盘点缺口，不在方案待确认时批量制作。
4. 映射实时模式和可选参数。区分总片长、实际使用长度、每次生成或新增延长长度；延长输出是否包含原段按实时定义判断，不简单累加各文件长度。
5. 将计时、定时分镜、素材职责与制作建议更新到已有方案 Note，保留草稿／已确认／待决定的区别；按 question 关口实际提问并读取答复，补齐制作确认。用户确认与生成请求均已覆盖本次范围后才进入执行。定时分镜、任务划分和最终 Prompt 使用同版内容。

完成条件：片长有内容依据；内容、规格、路线及执行范围已确认或在明确委托范围内；必要镜头有来源，任务依赖可闭合。存在关键待定项时停在制作确认，不把计划完整当成获准执行。依赖后续结果的部分仍保留为计划。

### 三、当前阶段执行与交接

开始前检查最新用户反馈、当前方案版本、question 的实际答复、规格决定依据和本次生成授权；工具已调用但用户尚未答复不算通过。当前阶段依赖的画幅、时长、实际可选清晰度或声音仍待确认时，先提问并等待；有“先等等／不要生成／先改方案”或尚未确认的实质变更时，不提交原计划的新任务。通过后再按基础画布路由写入最终 Prompt、素材绑定和参数。Note 不能代替节点输入，制作任务表不能代替权威状态。首次写入、原子编排、验收、执行目标和恢复按基础画布。

需要改图或补图时先落实已批准的资产任务：使用适用图像节点产出衍生素材，按约定完成选图／审图，再把就绪来源绑定到 Seedance 2.5。已授权可直接继续且无待选项时不增设确认。真实来源、节点依赖及分阶段执行见[资产节点衔接](asset-preparation.md#生图节点与视频节点的衔接)，不把生图提交成功当作素材已可用。

经核验有完成事件并能恢复会话的宿主可在原授权内接续。宿主要求含视频生成或编辑节点的任务非等待提交时，取得可靠任务编号后立即交接，本轮不自动续查。用户后续明确查询或继续时按对应流程恢复；不得用轮询、替代接口或重提交绕过交接。提交未知或失败不视为完成。

“继续”按暂停位置解释：方向待反馈时仅推进到用户已同意的创作步骤；制作方案仍有未决项时先解决该项；已获完整生成授权并因任务未就绪交接时，才恢复已确认任务并按基础画布允许的入口核验。只问任务状态就只查状态，不顺带提交下一段。仍在途则反馈并停止；提交当轮的“全部做完”不是交接后的新查询请求。

整片授权、来源就绪与执行交接分别判断。“全部做完／不用再问”仅在它指向明确方案或明确全权委托时覆盖相应范围，不取消基础交接边界，也不允许依赖未知结果生成。用户后来的反馈、范围收缩或暂停要求覆盖旧委托，不能用先前“不用再问”忽略新意见。保存后续依赖，不承诺当前机制不支持的无人值守续跑。

### 轻量变体

- 单一动作、氛围或展示：目标与素材职责 → 描述及估时 → 简明制作方案确认 → 获准执行。前两阶段可合并，不强制建表或 Note；用户已有完整指令和生成授权时不重复确认。
- 结构化短片：信息节拍与方向反馈 → 视听脚本、粗分镜、计时与任务表 → 制作确认 → 获准执行。
- 多场景、多角色或长叙事：完整三阶段；风格／主角等需要试片决定时在原方案中约定看第一段再推进，不临时新增试制。已明确批准整片或批量执行时不机械每镜请求批准。
- 局部编辑、延长、转场：复用既有内容，只规划受影响范围，不重走全片编剧流程。

## 规格、候选与授权

默认一个候选，不主动询问抽卡次数、单次还是多次或预算偏好。用户要求多候选／多版本时才补齐缺失数量与费用范围。一条成片的必要分段属于同一候选，但各段与后期的费用仍需纳入方案。

已指定规格直接沿用；模式继承或锁定的项只说明，不询问不可选项。用户尚未确定且实际可选的时长、画幅、分辨率／质量档及影响结构的声音需求，先提出推荐，再集中确认。“模型支持”“常用值”“我已经定好了”均不能把待定项转成已确认。“立刻开始”“高质量”不等于最高档或自行选规格；已授权 Agent 决定时仅在该项范围内选择，生成权限另行判断。

创意、剧本和创作分镜循环必须先于未给定规格的确认；生产分镜、生成节点和最终 Prompt 在确认后进行。依赖未定规格的生成节点不能用临时默认值代替缺失决策；独立分析、已明确的资产阶段或必要 Note 按基础画布的当前阶段屏障处理，不因整片未定而一律禁止写入。

只要求方案、脚本或改 Prompt 不等于要求付费生成；用户已经要求按确定方案生成且规格与费用范围齐备时直接执行。等待确认时完成不依赖该决定的工作，不为无关细节增加批准步骤。

“已确认”须有用户要求、反馈或明确委托作为依据，不能由 Agent 自己补齐方案来证明授权。用户提交完整可执行要求并明确让生成，或接受已展示方案并让开始时，可执行该范围，不逐节点重复询问。仅表达制作意愿而关键内容仍由 Agent 首次提出时，先展示并等待意见。金额上限与先报价要求必须满足；价格不可得时如实说明，不能宣称符合无法核实的预算。增加超出授权的候选、试制、音乐／后期，改变用户已锁定内容，或作出超出明确委托及费用范围的实质变更时，先展示影响并确认；委托范围内的调整说明即可。

## 制作路线由分镜决定

| 主要需要 | 优先评估的路线 | 关注点 |
| --- | --- | --- |
| 连续表演、同一主体／产品、空间探索、相机与声音接力、设计好的无缝换场 | **优先：起始段加延长** | 真实前段、边界、累计限制、输出组成 |
| 跨时空、多场景，但交付是一条连续成片 | **默认：单条串行延长主链** | 为换场设计动作／遮挡／光线／形状／运镜／声音桥；一次只建当前段 |
| 用户明确选择硬切蒙太奇、并联制作或独立返修 | 独立镜头加必要后期 | 主体／风格一致、空间关系、声音连续，以及用户对路线的确认 |
| 部分镜头已可用 | 复用加定向生成／编辑 | 实际内容是否满足目标，避免整片重做 |
| 严格时长、字幕、Logo、UI、混音或成片资源交付 | 素材制作后进入精确后期 | 真实资源与时长、源片／原声保持范围 |

允许混合路线。此表用于专业推荐，不是自动选型授权。**用户要一条成片且需要多轮生成时，单条串行延长主链是默认路线；片长和场景数只决定计划，不授权并联建节点。**同一主链具备实时延长能力时，不把独立生成加拼接当作同等无成本替代。说明路线对一致性、可修改性、串行依赖、段数和费用的影响，让用户决定尚未委托的项；用户已授权 Agent 决定路线时按本优先级选择。不可实现时展示阻塞与替代方案并等待取舍，不能静默切换路线。

### 视频延长优先保证一致性

以下任一连续性是核心目标，且没有下文独立制作理由时，将延长作为首选生产路线：

- 主角、产品、服装、道具或场景需要跨段持续保持；
- 动作、表演、对白、环境声或画内音乐尚未结束，需要自然接续；
- 相机运动、空间探索、视线引导或遮挡／光线转场要形成一条连续路径；
- 书本、门、镜子、手机、产品、人物手势或其他元素反复承担转场，需要保持其形态、接触关系和动态状态；
- 用户要求一镜到底、假一镜到底、无缝延续，或已有可用片段需要继续发展。

反复承担转场的元素是连续性载体，不是可在每段重新抽取的装饰。共享一张参考图不能传递上一段真实生成出的开合角度、手位、翻页方向、形变、相机和声音状态；例如“每翻一页进入一个世界”必须沿同一本书的真实结果逐页延长，不能把每一页并联生成。

起始段不仅是第一条独立视频，也是后续链的连续性基线。生产分镜应让它建立主体、空间、光线、表演和声音，并在叙事自然的位置留下可识别的动作、视线、相机或声音接续点；不为延长而制造无意义的半截动作，也不改变内容母版的镜头意图。同一模型生成的可用源片继续交给该模型延长时通常更利于音画衔接，但这是质量经验，不是无缝保证；实时支持仍按基础画布核验。

出现以下情况时才选择独立生成，或把它作为新的延长链起点：用户明确确认硬切蒙太奇、并联制作、独立版本或逐镜返修；上游片段存在用户不希望继承的错误；实时模式经核验不支持所需延长；两段必须使用互不相容的真实来源。明显时空断点、角色／产品／场景彻底更换可以成为路线建议，但不能单独视为用户已授权并联。真实来源尚未就绪时应等待并交接，不得因此改成独立生成。场景变化优先通过动作、遮挡、光线、形状、运镜或声音桥纳入同一延长链。

复杂影片先按**一条成片、一条主链**规划。只有已确认的硬切／并联路线或经核验无法延长的断点，才拆成多个连续性块；每个块内部仍采用起始段加逐轮延长。不能因为剧本写成五幕就同时创建五个普通 Seedance 节点，也不能用阶段预览把并联节点包装成顺序链。执行时严格遵守[完整规划、逐段实例化](sequential-extension-chain.md#完整规划逐段实例化)。

节拍、镜头、生成任务不强制一一对应：一个节拍可以跨任务，一个任务也可含多个相容短镜头。分段避开关键台词中间、难以恢复的接触或运动，必要时设计可辨认接续点。不为填满上限添戏，也不为每任务一个节拍切碎表演。

延长需要真实可用来源，计划尾状态与实际尾状态分开记录。角色短剧先依[人物三视图与录音](cast-and-dialogue.md)完成并确认全套资产，每段视频直接绑定该段人物图、正式录音和分镜文本。首轮视频只创建和提交起始段；未来段留在 Note／任务表，不创建占位视频节点。每段结果就绪后，按媒体理解路由取得下一段必要的真实边界，再创建或更新唯一一个下一段延长节点并重写该轮局部 Prompt；不能把计划尾状态当成事实。延长链必须顺着真实来源串行推进，不能先生成依赖未完成上游的高潮，不能一次提交首段和未来延长段，也不能为等待方便改成独立生成。

后期节点选型与阶段结构以基础画布为准：仅简单顺序串联且满足其交付条件时可使用 VideoCompose；精确编辑、字幕、配乐、严格时长或最终资源交付等按路由使用 VividCut。VividCut 来源未就绪时，基础流程要求的阶段 VideoCompose 仍需建立，不能把它当作最终剪辑，也不能提前写入缺少真实来源的剪辑片段。质量层“不使用旧拼接节点”的概括不取消这些基础路由。

## 技术核验、接续理解与观感验收

- 技术核验：任务状态、资源可用、真实时长、模式和结构依赖，按基础画布执行。
- 必要接续理解：为已授权下一段获取真实人物、动作、相机与声音边界，按基础媒体理解路由，仅检查接续所需信息。可复用可靠信息时不重复分析。
- 观感验收：评价好坏、寻找瑕疵并据此重抽。默认由用户查看；明确要求检查或反馈后才处理，不以接续理解为名扩大为自动质检。

读取到资源不等于已理解其内容，计划结束状态也不是实片事实。缺少必要语义边界时按路由获取；路由或授权不允许时交接所缺信息，不猜测。制作授权不代表无限重试。

## 音乐连续性

先按声音主模式确定是否允许背景音，再明确声音的叙事作用。未选择带背景音、未给出更具体组合且未明确委托时，不新增付费音乐任务。需要全片统一音乐时选择：

1. 原生音乐接续：首段含音乐，后续用支持音画接续的延长；核验能力，不保证完美无缝。
2. 后期统一配乐：片段保留约定人声、环境音与音效，不生成 BGM；复用用户音乐、已授权素材或按需确认的音乐生成结果，由后期统一编排。独立镜头需要同一音乐轨时采用此路线。

相同风格、Prompt 或参考音频不能证明独立生成的 BGM 连续。禁止 BGM 只排除背景音乐，不等于静音。统一配乐不等于必须新生成一条覆盖全片的音频。

情节直接要求的画内声源，如八音盒发声、角色弹琴或收音机播放，属于该事件的声音设计，不因带有旋律就自动当作额外背景配乐；仍遵守用户明确的静音或禁用声音要求。没有剧情依据时不借此添加配乐。

新增音乐纳入时长、情绪节奏、是否纯音乐与费用范围。明确作为 BGM 且用户未禁止循环时，按基础 BGM 填充流程处理其默认循环，并说明实际铺设方式，不承诺接缝听觉无感；对白、旁白、环境音或职责不明音频不套用 BGM 循环。需要不可重复的连续发展、完整乐句或用户禁止循环时，选足长素材、生成或确认接续方案，不用默认循环破坏创作要求。不自动增添未要求的淡入淡出、变速或静音。

## 剧本阶段保存 Note，与可恢复规划

**触发与时机**：用户已经要求在画布中制作或维护项目，且任务需要故事剧本、多镜头或结构化信息脚本时，默认在剧本阶段保存一份“创作与分镜方案”Note，无须额外追问是否保存。用户明确要求剧本放到画布时，无论篇幅长短都按请求保存。在既有画布项目中说“先写剧本／先别生成”，表示先做规划，不等于禁止保存非执行笔记；明确“只在聊天给我／不要修改画布”时才留在聊天。简单单动作、局部编辑、延长或转场不为形式新建长篇笔记；已有方案受影响则更新相关部分。

**正文内容**：根据当前阶段保存真实产出，而不是只有步骤标题或一句摘要：

- 目标、受众、用户保持项与创意方向；
- 故事梗概／信息主线、节拍、情绪与节奏；
- 完整场景剧本：具体动作、对白／旁白、必要声音与变化；
- 当前创作分镜、内容所需片长估算及依据；确认规格后补充定时／生产分镜，不提前编造交付秒数；
- 素材职责、可用性结论、用户要求的修改与保持项、待补资产及必要参考分析／拉片结论、制作路线建议与依赖；
- 用户已确认项、明确委托项、草稿和待决定项。

一份笔记随阶段逐步充实，初稿不必填满尚未开展的栏目。大型项目确需独立拉片或素材分析文档时按用途拆分，不为每个镜头、每轮修改或每个执行节点另建 Note。

**维护与用户反馈**：先按基础画布的画布笔记流程读取必要现状，再创建或定向更新，不盲目覆盖已有正文。用户修改剧情、分镜、声音或时长后，在授权的修改范围内同步同一份 Note，保留未改内容；新增内容在用户反馈前仍是草稿。记录简短的内容版本和确认状态，不把写入成功当作内容获批。聊天说明笔记位置、主要变化与待确认项，不重复粘贴整份长剧本，用户要求全文时再展示。

**执行边界**：Note 是非执行 Markdown 内容，不连接生成节点，不作为运行目标，不存内部身份或临时地址。最终 Prompt 和参数仍写入对应执行节点，Plan 管动作与状态；不额外建立重复的 Prompt、执行计划或交付 Note。只有基础流程确认写入成功且必要验收完成后，才能说笔记已保存。笔记能力不可用或写入失败时说明未保存，提供聊天草稿供审阅并保留待保存事项；不能假报成功或用付费文本生成节点替代笔记。基础恢复要求停止时照办。

宿主提供原生 Plan 时用它管理动作、依赖、产出与状态；不可用时如实说明，只维护可用工作记录，不假称已创建 Plan，也不因此阻止其他可行工作。内部恢复身份按基础画布保存，不写公开 Note。

恢复记录说明最终交付、内容版本、三层语言、用户已确认／委托项、Agent 建议与待反馈项、生成授权及其依据、当前阶段、已完成内容、在途／未知任务、实际依赖与下一步。用户说继续时先按暂停位置确定推进范围，再按需核验真实状态，不将待反馈项自动转为通过。不能因英文工具返回切换语言，也不能把旧版授权套到未确认的新版本。

素材补齐、剧本／分镜变化、任务结果、后期开始或用户改需求时，更新未完成部分。保留历史、成果和在途任务，不因重规划重复提交。Prompt 与参数直接维护在执行节点；同类 Note 不重复建，用户未要求时不在聊天再次粘贴长文。

## 修订与交付

先回应用户意见并指出影响范围，再按最小影响面修订：单一事件／保持项 → 时间段或局部元素 → 镜头 → 场景 → 整片。情节变化后检查台词、时长、素材与接续，保持同版；展示关键改动，用户只要求修改方案时停在修订结果，明确要求改完生成且范围齐备时才执行。Prompt 整合为完整新版本，不追加矛盾补丁。

用户要求暂停或改变方向时停止提交新的受影响任务。已提交任务如何处理服从基础画布，不虚称已取消；先说明其真实状态，再与用户处理后续方案。

已有结果节点的保护与复制按质量层，真实操作按基础画布。无用户要求不为随机差异增加候选；额外费用、扩大数量或改变已确认内容时集中说明。失败、未知状态与恢复按基础规则，不能用换节点或重规划绕过停止条件。

交接说明已完成什么、仍缺什么、如何继续；完成授权内容后交给用户查看。提交成功不等于生成完成，生成素材不等于最终剪辑完成。
